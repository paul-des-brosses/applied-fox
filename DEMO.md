# Applied Fox Demo — Step by step

> You can run this demo in under 30 minutes on a clean machine.
> No API key required for the minimal mode (Reddit + RSS).

## Prerequisites

- Python ≥ 3.11
- [Ollama](https://ollama.com/download) installed and running (the service runs in
  the background once installed)
- Git
- 10 GB free disk space (mistral 7B ~4.4 GB + qwen3:8B ~5 GB)

## Step 0 — Installation (5-10 min)

```bash
git clone <repo-url>
cd applied-fox-agent-ia
bash setup.sh                  # venv + deps + Ollama check + LLM model pulls
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .
```

At this point:
- The venv is created in `.venv/`.
- The `mistral:7b-instruct-q4_K_M` model (~4.4 GB) is downloaded via Ollama.
- The `applied-fox` command is available.
- A default config is created in `~/.applied-fox/config.yaml`.

> **Important**: `setup.sh` only pulls `mistral:7b`. Before the first run,
> you also need the Judge's model:
> ```bash
> ollama pull qwen3:8B   # ~5 GB
> ```
> If `qwen3:8B` is missing, the pipeline will crash at the Judge step. See
> `docs/HARDWARE.md` if you cannot fit both models in VRAM.

Verify:
```bash
applied-fox --help
```

## Step 1 — Open the menu (5 sec)

```bash
applied-fox
```

You see a table of available projects. On first launch, it is empty. Type
`n` to create a new project file, OR reuse the example file shipped with
the repo:

```bash
# Option A: point to the example file in the repo
# Edit ~/.applied-fox/config.yaml to add:
#   paths.projects_dir: /absolute/path/to/applied-fox-agent-ia/projects

# Option B: create a new project file via the TUI
# (from the menu, type 'n' then follow the questionnaire ~5 min)
```

## Step 2 — First watch cycle (3-25 min depending on cache)

From the menu:
1. Pick your project by its number.
2. Choice `1` — "Run a new watch cycle".
3. A progress bar shows the 4 stages:
   - Scout — collection + filters (~1 min cold post-MVP, was ~15 min in early versions)
   - Integrator — feasibility verdicts (~3 min)
   - Judge — relevance + timing (~10 s thanks to v1.5 deterministic filters)
   - Reporter — synthesis + report (~1 s, single LLM call)

At the end, a panel summarizes:
- Number of raw findings collected
- Number of Integrator / Judge verdicts
- Number of final suggestions (typically 3-8, sometimes 0 if signal is weak)
- Path to the HTML report

## Step 3 — Validate suggestions (5-10 min)

The menu automatically offers:
> *Validate suggestions now?*

Press Enter (yes). The Rich TUI opens:
1. A recap table of all suggestions.
2. For each: a detailed panel (title, what changes, affected components,
   effort, risks, open questions).
3. For each, choose:
   - `a`: **accept** — will be offered for integration.
   - `r`: **reject** — definitively discarded (optional reason).
   - `d`: **defer** — pushed back (optional reason).
   - `p`: **pass** without decision, silent defer equivalent.
   - `b`: **back** to the previous suggestion (from the 2nd onward).
   - `v`: **view** the HTML report in your browser (if available).

At the end, a decision recap is shown. Confirm with Enter to save to
`<run_dir>/05_user_validated.json`.

## Step 4 — Integrate accepted suggestions (5-15 min)

The menu offers:
> *Integrate accepted suggestions into the project file?*

Press Enter. For each accepted suggestion:
1. Clear recap of the suggestion.
2. If the suggestion has **open questions** (e.g., "which battery to pick?"),
   you answer via a mini-questionnaire.
3. The `.md` file is regenerated with the changes.
4. The **3 validation layers** kick in:
   - Structural (Pydantic + Markdown parsers)
   - Transmission (a third-party LLM summarizes the file, you verify the summary is faithful)
   - Human (recap of modifications, you validate)
5. If OK, the file is written. Otherwise, rollback and the original file
   is preserved.

## Step 5 — View the report (1 min)

Anytime from the menu:
1. Pick your project.
2. Choice `2` — "Browse past runs".
3. A table lists all runs with date, finding count, suggestion count,
   and whether an HTML report exists.
4. Type a run number to open the report in your browser.

The report contains:
- **One-line synthesis** generated by the Reporter.
- **To consider now**: 3-8 prioritized suggestions with full rationale
  (required changes, risks, effort, additional sources).
- **Noted for later**: findings noted but not priority (includes those
  downgraded by Judge filters B/C).
- **Rejected (with reason)**: audit trail of discarded findings, deterministic reasons included.
- **Consulted sources**: breakdown by source type.

## Step 6 — Second run with incremental mode (3-5 min)

Re-run the same project:
```bash
applied-fox
# pick project → 1 (new run)
```

This time:
- The **LLM cache** makes most calls free (~10× faster).
- **Incremental mode** does not re-surface findings already seen on the
  previous run (state stored in `~/.applied-fox/state/<project>_seen.json`).

You observe the complete pipeline in a few minutes instead of 25.

## Demo troubleshooting

**`ollama: command not found`**
→ Ollama not installed. See https://ollama.com/download

**Pipeline crashes with `Connection refused`**
→ The Ollama service is not running. Run `ollama serve` in a separate
terminal, or reboot the machine (the service auto-starts on Windows/macOS).

**Pipeline produces 0 findings on the 2nd run**
→ Normal — incremental mode active. To reset:
```bash
# Linux / macOS / WSL2
rm ~/.applied-fox/state/<project>_seen.json
# Windows PowerShell
Remove-Item "$env:USERPROFILE\.applied-fox\state\<project>_seen.json"
```

**The HTML report does not open in the browser**
→ Under WSL2, `webbrowser.open` may fail to find a browser. Open the
`04_rapport.html` file manually using the path shown on stdout.

**First run very slow (40+ min)**
→ Normal in cold without cache. Check your config: `max_after_filter: 80`
caps the work. The 2nd run will be ~10× faster thanks to the LLM cache.

**`Layer 2 validation` fails repeatedly during integrate**
→ The third-party LLM struggles to summarize your file. Check the output
to understand what's missing. If blocking, temporarily disable layer 2
in config (planned — for MVP, accept the recap screen).

## 5-minute demo script for jury / recruiter

If you present the project live:

1. **Open the menu** (`applied-fox`): show the project table.
2. **Choice 2 (past runs)**: open an already-produced HTML report. Show
   prioritized suggestions and the rejection audit trail.
3. **Back to menu, choice 3 (validate)**: show the validation TUI,
   detailed panel, accept/reject/defer, final recap.
4. **Choice 4 (integrate)**: show open questions and the 3 validation
   layers. Stress that the user remains the arbiter.
5. **Exit and open `docs/ARCHITECTURE.md`**: explain the 4-agent pipeline
   on the diagram, and `src/llm/__init__.py` for hot-swap.

You can do all of this in under 5 minutes if your runs are already cached.
